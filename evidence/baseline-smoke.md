## 2. Где действует ограничение размера загрузки

Цель — установить, в какой момент срабатывает лимит 5 МиБ. Код продукта не менялся: обработчик `read_limited` подменён снаружи обёрткой, которая печатает состояние загрузки до проверки размера.

```python
# probe_spool.py — запуск: .venv/bin/uvicorn probe_spool:app --port 8771
import app.main as m
original = m.read_limited
async def probed(upload, max_bytes):
    f = upload.file
    print(f"PROBE size_before_read={upload.size} rolled_to_disk={getattr(f, '_rolled', None)} "
          f"backing={type(f._file).__name__} limit={max_bytes}", flush=True)
    return await original(upload, max_bytes)
m.read_limited = probed
app = m.app
```

| Файл | Ответ | Получено до `read_limited()`, байт | Где хранится |
| --- | --- | --- | --- |
| `valid.png` | 201 | 1 952 | память (`BytesIO`) |
| 1 000 000 байт нулей | 415 | 1 000 000 | память (`BytesIO`) |
| `too_large.bin`, 6 МиБ | 413 | 6 291 464 | временный файл на диске (`rolled_to_disk=True`) |
| 100 МиБ нулей | 413 за 0,09 с | 104 857 600 | временный файл на диске (`rolled_to_disk=True`) |

**Вывод:** лимит 5 МиБ ограничивает файл, **принимаемый к обработке**, но не ограничивает **входящий трафик и временное использование диска**. Starlette 1.7.0 разбирает multipart-тело целиком до вызова обработчика; часть файла сверх 1 МиБ (`spool_max_size` в `starlette.formparsers`) записывается во временный файл. В пределах baseline верхней границы объёма тела запроса нет: 100 МиБ были приняты полностью и только затем отклонены. Ответ 413 при этом корректен.

## 3. Срок хранения: недоступность и физическое удаление

Запуск с `RETENTION_SECONDS=3 CLEANUP_INTERVAL_SECONDS=60`, хранилище — чистый каталог `data/`.

| Момент | Наблюдение |
| --- | --- |
| 0 с | файл 1 загружен; в `data/<id>/` есть `meta.json`, `original`, `thumbnail.png` |
| 5 с, запросов к файлу не было | срок истёк 2 с назад, все три файла **остаются на диске** |
| 5 с, `GET /files/{id}` | 404; каталог удалён в ходе этого запроса |
| файл 2 загружен и не запрашивался | каталог удалён фоновой очисткой через 50–60 с после загрузки |

**Вывод:** после истечения срока файл недоступен через API сразу (проверка при каждом обращении), а физически удаляется при первом обращении либо при ближайшем проходе фоновой очистки. С настройками по умолчанию задержка физического удаления — до 60 с; очистка выполняется в том же цикле событий, что и синхронная обработка изображений, поэтому идущая обработка может её отложить. Пока сервис остановлен, просроченные файлы не удаляются; очистка выполняется сразу при следующем запуске.
